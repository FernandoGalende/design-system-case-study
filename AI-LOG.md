# AI log

## Key decisions

- Configuration through inputs, content through projection: the alert's variant, heading, icon
  and dismiss options are inputs, while its body, action and custom icon are projected; the card
  is all slots (rows 3, 7, 15–17).
- The alert is controlled: it only emits `dismissed` and the parent removes it, so focus handling
  after dismiss stays with the parent (rows 7, 19, 24).
- Live semantics: `polite` renders `role="status"`, `assertive` renders `role="alert"`, `off` no
  role; errors default to assertive, the rest to polite, and alerts present on load use
  `live="off"` (rows 7, 9).
- Tokens are explicit per role, with shared foundations once in `:root` and only brand-specific
  values in the brand blocks; component internals are private `--_*` properties (rows 3–6, 13).
- The card's default slot is the body, so content outside the named slots is never dropped
  (row 15).
- Responsive behavior uses container queries, so the alert adapts to its container, including
  inside a narrow card (rows 8, 28).

## Where I corrected or challenged the AI

- Renamed the type scale to sm/md and moved the alert's sizing constants out of the global token
  file (row 4).
- Replaced the proposed `::ng-deep` with an attribute-selector action component (row 3), and
  rejected a global `@layer` reset for card content (row 14).
- Kept all four variant-default tests instead of trimming them to the code's branches (row 12).
- Rejected "no default slot" for the card: unmatched content would be dropped silently (row 15).
- Chose the spec's brand rule (violet/teal action) over the mock after the AI questioned it
  (row 27), and went back to the spec's outlined error icon instead of the filled one the AI had
  recommended, recording the color-only trade-off (rows 22, 33).
